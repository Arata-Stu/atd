# atd_planning

タイムアタック用の参照軌道を計算し、プロポ手動走行中の車両と保存ラインの関係を観測する。Jetson の `/localization/status` を購読し、`/planning/status` (`atd_interfaces/msg/PlanningStatus`) を配信する。Pico・ESC の出力はプロポ手動走行のまま試せる。

`line` は `raceline`（既定）、`centerline`、`custom` から選ぶ。対象は地図画面で生成・保存したライン。`hdmap/map.json` の `lines[line].points` と `profile` の座標・弧長・速度を照合する。Customline は開路も利用でき、終点で前方軌道が終わる。

各観測では後輪軸中心をラインの線分上に投影する。初回は位置と車体の向きから候補を選び、追跡中は経過時間・速度・前回の弧長で検索範囲を絞る。閉路の始点を越えると `progress_m` は 0 m に戻る。方位または距離が合わない場合や、近接区間を一意に選べない場合は計画を無効にする。追跡世代やセッションの変更、観測の中断後は再投影する。

| 観測量 | 意味 |
| --- | --- |
| 前方軌道 | map 座標系の投影点から前方までのライン頂点列。既定の前方距離 2.0 m。各点の目標速度も配信する |
| 横ずれ [m] | ライン進行方向に対する車体位置の横成分。左が正、右が負 |
| 目標速度 [m/s] | 投影点のプロファイル速度。線分間では保存プロファイルの等加速度式に合わせて速度の二乗を距離で補間する |
| 推定速度 [m/s] | 同じ自己位置観測が報告した車体前後速度。前進が正 |
| 有効期限 [s] | 元観測から 0.5 秒。ROS 時刻と steady clock の両方を検査する |

地図 ID・cuVSLAM 地図と HDMap の SHA256・追跡状態が整合し、有効な観測がある間だけ軌道を返す。ラインが欠落している場合や追跡喪失中は空の軌道と理由を返す。launch の `max_offset_m` は投影距離上限（既定 0.75 m）、`horizon_m` は前方距離。いずれも観測用の初期設定。

別 bag の検証は Notebook の自己位置検証に保存した軌跡、区間、地図と速度プロファイルを使う。ROS に依存しない同じ `atd_planning.core.Planner` がオンライン・オフラインの両方で投影と前方軌道の生成を行う。
