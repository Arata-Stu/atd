# Notebook で先読み距離を比較する

ATD Studio の「シミュレーター」で、同じサンプルコースを固定先読みと速度連動先読みで走らせる。計算は Notebook 内で完結する。入力には同梱のコースと仮の車両特性を使う。

## 起動と比較

Monza の直線から最初のシケインを D455 視点で見るには、Linux Notebook ホストで別の Gazebo 環境を起動する。[左右動画と配信計測](gazebo_monza.md)

Notebook の Docker 内で実行する。初回と Web UI の更新後に、オンラインで `atd-web prepare` を一度実行する。準備後はオフラインで起動できる。

```bash
atd-web
```

1. Notebook のブラウザで[シミュレーター](http://127.0.0.1:8766/#simulation)を開く。
2. 固定側の先読み距離と、速度連動側の最小距離・先読み時間・最大距離を指定して比較する。速度連動側の距離は `min(最大距離, 最小距離 + |車速| × 先読み時間)`。
3. コーナーを選んで見るときは、時刻を動かし、地図上の車体位置と横ずれ・速度・操舵のグラフを照合する。両車の経過時間が同じでも、コース上の到達位置やそこでの目標速度が異なる場合がある。
4. 遅延の影響を見たいときは、両条件に共通の操舵むだ時間だけを変えて再計算する。例えば 0、50、100 ms は感度を調べるための仮定値として使える。スロットル側も別に試せる。

計算の各ステップでは、後輪軸の模擬位置・向き・車速を既存の `atd_planning` の Planner に入力する。前方軌道を Pure Pursuit に、現在の目標速度と模擬車速を既存の FF＋PID に渡す。得た舵角とスロットルで平面自転車モデルの状態を進め、その結果を次の観測とする。初期姿勢、コースの速度プロファイル、FF 表、PID、車両モデルと刻み時間は両条件で共通にする。FF 表と車両特性はシミュレーション専用で、走行用の校正ファイルとは独立している。

サンプルは半径 0.85 m のヘアピンと半径 2.15 m のコーナーを直線でつないだ 1 周約 23.27 m のコース。直線の途中で基準ラインの左 6 cm に静止した状態から、2 周を走る。直線の目標速度は最大 1.95 m/s で、コーナーに向けて下がる。模擬車両はホイールベース 0.257 m、舵角上限 ±28°。コントローラは 20 ms ごとに更新し、グラフは 100 ms 間隔と走行終端の値を表示する。

横ずれは参照線に対して左が正、操舵は左旋回が正。速度は前進方向の模擬車速、舵角は単一の等価前輪の角度。操舵の飽和時間は、Pure Pursuit の指令角がモデルの舵角上限を超えた時間の合計。タイヤの横滑り、ステレオ画像の追跡誤差、Tamiya ESC のブレーキ・後退への切替は今回のモデルの範囲外。

## F1 コースでベンチマークを実行する

同梱の20コースは、F1TENTH の配布形状を ATD の 1/10 RC 車両モデル向けに調整したもの。走路の内外境界と、そこから ATD の既定設定で生成した Centerline・Raceline を保存している。初回の地図ダウンロードは不要。[全23件の採否とレイアウト](f1_circuits.md)・[元 CSV と生成済み HDMap](../samples/f1tenth/)

1. [シミュレーターの「F1 ベンチマーク」](http://127.0.0.1:8766/#simulation?view=benchmark)で「同梱の全20コース」または「選択したコース」を選ぶ。規定周回数、初期条件の数、走行ライン、先読み・遅延設定を指定し「評価を実行」を押す。別画面に移っても Notebook 側のジョブは継続する。「評価ログ」から進捗の確認と中止ができる。
2. 評価表で固定・速度連動それぞれの完走率、衝突数、平均・最速ラップを見る。コース名を押すと個々の試行と各周のタイムが開く。履歴の「差分の比較元」で、同じコース・ライン・周回数・初期条件を使った別の設定や実装との結果の差を表示できる。コース別集計は CSV、試行ごとの結果・モデル・入力と実装のハッシュは JSON で保存できる。完了した評価は Notebook の `/data/results/runs/simulation_benchmarks/<run_id>/report.json` に残る。
3. 場所を調べたいときは「走行比較」で同じ地図、ライン、開始姿勢、周回数、制御設定を選ぶ。左右の境界と2本の軌跡が重なる。× は最初に壁との接触を検出した計算区間の終了時の車両位置。時刻を選び、横ずれ・操舵指令・模擬舵角を照合できる。
4. 境界・速度上限を変えるには対象コースの「編集用 HDMap を作成して開く」を押す。「地図とライン」で境界を保存した後に Centerline、Raceline の順で再生成する。シミュレーターでそのコースと「保存済みの編集用コピー」を指定すると変更後のラインで評価できる。「同梱の全20コース」は常に配布した地図とラインで比較する。

**評価の読み方**

- 既定値は各方式3試行 × 2周。全方式で同じ始点から静止発進し、① ライン上・進行方向、② 左へ 6 cm・姿勢 +3°、③ 右へ 6 cm・姿勢 −3°の順に試す。1試行を選ぶと①のみ。完走率は規定周回を終えた試行数を実行試行数で割った値で、実車の成功確率とは別の指標。
- 衝突は生成設定の車体寸法（長さ 0.35 m、幅 0.19 m）の長方形を使い、各移動区間で車体が通過した領域と内外境界の接触を検査する。最初の接触でその試行を終了し、追跡喪失・制御計算中断・時間超過は個別に記録する。
- タイムは選択した走行ライン上で1周分の進捗を通過した時刻を補間して求める。第1周には発進時間を含む。平均と最速は全試行の完了した周から計算する。途中終了した周は含めず、完了した周がなければ「—」になる。ラップの短さと完走率を合わせて見る。
- 既定の速度上限は 1.5 m/s。今回生成した全20コースの Raceline は全点の目標速度がこの上限に達する。速度変化への追従を比較する場合は、例えば編集用地図の横加速度上限を下げ、曲線部で目標速度が落ちるプロファイルを再生成する。模擬速度 FF 表の範囲は 0.2〜3.2 m/s。コーナーのバンクやタイヤ横滑りを含む実車性能の測定には実走行が必要。

同梱した[基準評価結果](../samples/f1tenth/baseline.json)では120試行すべてが2周を完走し、衝突は0件。Austin での平均ラップと平均横ずれ RMS は、固定先読みが 48.885 s・0.58 cm、速度連動が 48.734 s・2.06 cm だった。平均横ずれ RMS は各試行で経過時間に対して計算した RMS の算術平均。初期姿勢の選択・車両寸法・むだ時間によって結果は変わる。

## 実車の遅延をどう推定するか

「むだ時間」は指令が変化してから応答が始まるまでの時間、「時定数」は応答開始後の立ち上がりの速さを表す。シミュレーターでは両方を個別に設定できる。実機がそろうまでは値に幅を持たせて比較し、走行後に入出力の波形から両方を推定する。一定の入力で直進しただけの区間から両方を決めるのは難しい。[むだ時間を含む一次応答の同定例（MathWorks）](https://uk.mathworks.com/help/ident/ug/building-and-estimating-process-models-using-system-identification-toolbox.html)

| 対象 | 同じ走行で照合する信号 | 推定値の意味 |
| --- | --- | --- |
| 操舵 | ほぼ一定速で小さな左右操舵を繰り返し、サーボの指令・Pico 報告 PWM と、車体座標の IMU ヨー角速度を比較 | 操舵して車体が旋回を始めるまでの有効な遅れ。サーボ単体の応答を知るには、車輪の実舵角も同期計測する |
| スロットル | 前進直進中に入力を段階的に変え、ESC の指令・報告 PWM と IMU 前後加速度、VSLAM の前後速度を比較 | 駆動系と車体を含む応答。加速開始は加速度、立ち上がり全体は速度で照合する。惰行・ブレーキ・後退は別区間として扱う |

記録には[車両校正用の bag](vehicle_calibration.md)を使う。入力元と CH3、基板の報告値、センサの元時刻が対応する区間を選び、時刻系とサンプリング間隔を確認する。Pico の PWM 報告には Jetson 受信時刻が付く。これは物理端子のパルス開始時刻とは異なる。VSLAM の平滑化や姿勢推定、車体の応答も観測波形に含まれるため、ソフトウェア経路と機械系それぞれの遅延を分離するには、追加の同期計測が要る。

同梱の Rev6 firmware では PWM は 100 Hz で、基板内の判定から次の PWM 周期境界までの待ちは設計上最大約 10 ms。CDC0 の出力状態報告は 50 ms 周期なので、記録上の PWM に現れた変化の時刻にはその分の粒度がある。実機計測前でもこの部分はコードから見積もれる。サーボが動き始める時刻や ESC 入力から車体が加速し始めるまでの時間は実測が必要。[PWM 周期](../ros2_ws/src/atd_vehicle_interface/firmware/pico_rev6/README.md)・[基板の出力状態報告](../ros2_ws/src/atd_vehicle_interface/firmware/pico_rev6/src/main.c)

同定する際は、複数の入力変化に対するモデル予測と観測の誤差が小さくなるむだ時間・時定数を探す。別 bag で応答の立ち上がりと速度・旋回波形を再現できるか確かめ、区間ごとに推定値がばらつく場合は範囲として扱う。この画面は値を入力して結果を比較するためのもので、自動同定は今後の工程。
