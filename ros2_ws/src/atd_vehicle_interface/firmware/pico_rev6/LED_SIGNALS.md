# Pico本体LEDの見方 — v0.2.0-led

追加部品なしで、RP2040版Picoの緑色LED（GP25）を使います。制御状態が変わると、その光り方を最初から表示します。

| 光り方 | 名前 | 意味 |
| --- | --- | --- |
| 2秒ごとに短く1回 | `WAITING` | ファームウェア動作中。USB認識・有効なSBUS受信のどちらもなし |
| 2秒ごとに短く2回 | `USB_LINK` | PC／JetsonがUSB機器として認識。USB制御は開始していない |
| 2秒ごとに短く3回 | `RC_READY` | SBUS受信は正常。プロポ制御／USB制御の開始待ち |
| 0.5秒点灯・0.5秒消灯 | `RC_ACTIVE` | プロポによる制御が有効 |
| 0.9秒点灯・0.1秒だけ消灯 | `HOST_ACTIVE` | Jetson側のUSB指令による制御が有効 |
| 0.1秒点灯・0.1秒消灯を連続 | `FAULT` | 受信喪失、failsafe、指令timeout、電源喪失など。異常を優先表示 |

短い点灯は120 ms、連続する短い点灯の間隔は250 msです。USBとSBUSを両方使う場合は、接続の数より**現在の制御状態**を優先します。中立のままでも制御が有効なら`RC_ACTIVE`／`HOST_ACTIVE`です。LEDは車輪の回転や実際の車両停止を計測していません。

JoyはJetsonへ接続するため、Pico単独ではJoyそのものの接続を判定できません。`HOST_ACTIVE`は、Joyまたは自動運転を含むJetson側から有効なUSB指令を受け、制御を許可している意味です。USBを挿しただけ、`PING`が返るだけ、あるいはCH3をJetson許可へ切り替えただけで`HOST_ACTIVE`にはなりません。

## USBだけで確認する場合

Rev6基板をUSBだけでPCへつなぐと、通常は短く2回ずつ光ります。起動後に一度もBEC電源正常が成立していない場合は、BECがないことだけをLEDの異常扱いにしません。サーボ／ESC出力の電源保護・禁止条件は従来のままです。

基板へ取り付ける前のPico単体でもLEDは動きますが、GP9の電源正常入力が未接続になるため、電源状態の表示は確定しません。2回点滅以外になった場合も、実基板上の電源異常と同じ意味には取らず、まずUSBの`INFO`応答で起動を確認します。単体確認のために電源正常入力をHighへ直結する必要はありません。

一度BEC電源正常が成立してからESCスイッチを切ると、USBでPicoが生きている間は`FAULT`になります。意図的に切った場合も同じです。BECが正常へ戻り、100 msの確認が終われば現在の状態の表示へ戻ります。起動時から低電圧で一度も電源正常にならない状態も、接続待ちと同じ表示になるため、電源正常の確認は下記の`power_ready`を見ます。

プロポ受信開始時や切替の確認中には、CH3未確定として一時的に`FAULT`が表示される場合があります。約0.1秒の判定後も継続するかで見分けてください。

## USBで表示理由を調べる

センサ／診断側のCDC1へ`LED`と改行を送ると、表示状態とその根拠を返します。出力を動かすコマンドではありません。

```text
LED state=USB_LINK usb=1 power_ready=0 power_seen=0 sbus_fresh=0 host_armed=0 path=3 fault=0x01
```

これはUSBのみで、BECがない場合の例です。

| 項目 | 意味 |
| --- | --- |
| `usb` | USB機器として認識され、suspendされていない |
| `power_ready` | 電源正常信号を100 ms確認できている |
| `power_seen` | 起動後、一度でも電源正常になった |
| `sbus_fresh` | 正常SBUSを50 ms以内に受信し、failsafeがない |
| `host_armed` | USB制御が許可され、有効な指令が継続している |
| `path` | 0＝待機、1＝プロポ、2＝USB、3＝異常／電源待ち |
| `fault` | 既存のJPB1と同じbit列。`0x01`はBEC電源未成立 |

異常が複数あってもLEDは同じ高速点滅です。詳細な理由は`fault`と[制御仕様](README.md#usbの契約)を確認してください。`LED`は現在の瞬間のスナップショットなので、切替直後はLEDの1 ms更新と表示の間に短い差が生じる場合があります。

## 更新するファイル

配布版 `v0.2.0-led-bench` の `jpbb_pico_rev6.uf2`、または[ATD のビルド手順](README.md#ビルド設定検証)で作成した同名の UF2 を使います。ESC/BECを切り、BOOTSELを押しながらUSB接続し、UF2を`RPI-RP2`へコピーします。macOS で ATD のビルド結果を書き込む場合は、リポジトリのルートから次を実行します。

```bash
cp -X ros2_ws/src/atd_vehicle_interface/firmware/pico_rev6/build/pico/jpbb_pico_rev6.uf2 /Volumes/RPI-RP2/
```

Pico 2／Pico W用ではありません。点滅処理にsleepは使わず、既存の1 ms制御割込みからGPIOだけを更新します。LEDは独立した安全回路ではありません。LEDパターンと状態遷移はホストテストで検証し、実機の光り方は更新後に確認します。
